1 User-story generation from requirements
This exercise turns a hiking-platform requirements specification into user stories through three linked questions:
whousesthesystem,whateachroleneedstodo,andwhythatactionmatters. Thesamerequirementstextfeeds
each extraction stage; a supplied CSV provides a reference set for role-level precision and recall. The process
ends by adding a purpose clause to a generated role/function pair. The results are model outputs evaluated
against this particular reference, not a proof that the requirements or generated stories are complete.
Figure 1: Notebook-provided architecture: requirements feed role extraction, then functions and purposes,
producing user stories.
1.1 Model setup and prompt serialization
The pipeline begins with a fixed seed, the available compute device, and Llama 3.2 3B Instruct loaded from the
locally authenticated Hugging Face account. The helper accepts chat-template prompts, avoids adding a second
BOS token, samples at temperature 0.15, and stops at either Llama’s end-of-turn or EOS token. After decoding,
it frees generated tensors and clears the MPS cache. These shared settings apply to role, function, and purpose
generation.

22defmake_a_query(prompt:str, tokenizer, model, device, max_new_tokens:int= 200):
23# Chat-template prompts already contain special tokens; do not add another BOS.
24inputs = tokenizer(prompt, return_tensors="pt", add_special_tokens=False).to(device)
25prompt_length = inputs["input_ids"].shape[1]

28output = model.generate(

34num_beams=1,
