     1 Quantization: from low-bit arithmetic to Llama inference
     This exercise first makes low-bit arithmetic visible on a small matrix and vector, where symmetric and asymmetric
     quantization can be compared directly. It then applies post-training quantization to Llama 3.2 1B, measuring
     serialized size and a fixed CPU generation workload across float32, PyTorch int8, and BitsAndBytes int4. The
     toy example isolates rounding, zero points, and accumulation overflow; the model experiment shows how these
     ideas behave in a real decoder-only network.

     The floating-point result is the numerical target for the quantized calculations that follow.
     This helper implements symmetric absmax quantization. Its scale maps the largest magnitude to 127, rounding
     maps values to integer levels, and clamping keeps them in the symmetric range from -127 to 127. The zero-range
     guard makes an all-zero tensor safe to quantize.
 1   def absmax_quantize(W):
 2       # NOTE: we assume that we always map to 8-bit integers
 3
 4       # TODO: find the scale factor that maps the maximum absolute value in W to the maximum value of int8
 5       max_value = W.abs().max()
 6       scale = torch.where(max_value > 0, max_value / 127, torch.ones_like(max_value)) # how "long" the step between any two
          int8 values is
 7
 8       # TODO: quantize W using the scale factor (hint: remember to round to the nearest integer and convert to int8)
 9       W_q = torch.round(W / scale).clamp(-127, 127).to(torch.int8)
10       return W_q, scale


        The function returns both integer codes and the scale needed to recover approximate floating-point values.
     Quantization is useful only if the integer representation can be interpreted again. This inverse helper converts
     the codes to float and multiplies by their saved scale.

     1.2 Min-max quantization and the zero-point correction
     Symmetric absmax mapping dedicates its range around zero, so it cannot use the extra negative int8 endpoint.
     Min-max mapping instead maps observed extrema to -128  P and 127. WithP zero points zW and zx , the recovered
     product must expand (qW − zW )(qx − zx ): subtract zx qW and zW          qx , then add KzW zx , where K is the
     inner dimension. Only after this correction do we divide by both scales.
     The second helper uses an asymmetric min-max mapping. It stretches the observed range to the full int8 interval,
     stores a zero point, and reverses both operations during dequantization. The constant-range guard avoids
     division by zero.
 1   def minmax_quantize(W):
 2       # the following notations come from:
 3       # (1) scaling W to [0,1] ==> W’ = (W - min(W)) / (max(W) - min(W)),
 4       # (2) scaling W’ to [-128, 127] ==> W_q = W’ * 255 - 128
 5       # by combining the two, we get that:
 6       # W_q = W * scale + offset
 7       # we will call the offset "zero_point", as it represent the value that maps to 0
 8
 9         # TODO: find the scale factor that maps the minimum and maximum values in W to -128 and 127
10         delta = W.max() - W.min() # the range of values in W
11         scale = torch.where(delta > 0, 255 / delta, torch.ones_like(delta))
12         zero_point = -128 - W.min() * scale # the value that maps to 0
13
14         # TODO: quantize W using the scale factor (hint: remember to round to the nearest integer and convert to int8)
15         W_q = torch.round(W * scale + zero_point).clamp(-128, 127).to(torch.int8)
     1.2    Min-max quantization and the zero-point correction                                                      5



16
17         return W_q, scale, zero_point
18
19   def minmax_dequantize(W_q, scale, zero_point):
20       # TODO: dequantize W_q using the scale factor and zero_point
21       dequantized_W = (W_q.to(torch.float32) - zero_point) / scale
22       return dequantized_W


        Unlike absmax, this mapping can use all 256 codes and need not map real zero to integer zero. The returned
     scale and zero point are both required to interpret the codes.
     We quantize the same matrix and vector with independent min-max ranges. Reusing the same examples makes
     the later error comparison meaningful.
 1   W_q, scale_W, zero_point_W = minmax_quantize(W)
 2   x_q, scale_x, zero_point_x = minmax_quantize(x)


        Each operand now carries its own scale and zero point; these are needed for both reconstruction and the
     corrected dot product.
     This check dequantizes the matrix, measures its mean absolute error, and prints the zero point so we can see
     how real zero is encoded.

 2   print(W)
 3
 4   #TODO: dequantize W_q and check how close it is to the original W
 5   W_deq = minmax_dequantize(W_q, scale_W, zero_point_W)
 6   print(W_deq)
 7   W_diff = (W - W_deq).abs().mean()
 8   print(W_diff)
 9   print("zero point", zero_point_W)

     The full int8 range is used and the matrix error is small. The nonzero zero point shows that a real zero is
     represented by an offset code rather than by integer zero.
     As in the symmetric case, the min-max integer dot product uses int16 accumulation. The result is kept in code
     space until the zero-point offsets are removed.
 1   #TODO: perform the matrix multiplication using the quantized values converted to int16
 2   out_q = W_q.to(torch.int16) @ x_q.to(torch.int16)


        This cell prepares the raw dot products; interpreting them as real values requires the correction terms in the
     next computation.
     Expanding the two affine quantization equations gives the corrected product. The row-wise matrix-code sums,
     vector-code sum, and shared inner dimension account for the cross terms introduced by both zero points.
 1   # Expand (W_q - zero_point_W) @ (x_q - zero_point_x).
 2   # Use the quantized operand sums, rather than the original floats: rounding
 3   # means the latter no longer give the same dequantized product.
 4   out_deq = (
 5       out_q.to(torch.float32)
 6       - zero_point_x * W_q.to(torch.float32).sum(dim=1)
 7       - zero_point_W * x_q.to(torch.float32).sum()
 8       + W.shape[1] * zero_point_W * zero_point_x
 9   ) / (scale_W * scale_x)


        The resulting expression removes the offsets before dividing by the product of scales. This is why asymmetric
     quantization cannot simply multiply the raw int8 result by two scales.
     We print the corrected min-max result beside the original output and compute their mean absolute difference.
     This closes the small numerical comparison.
 1   print(out_deq)
 2   print(out)
 3   print((out_deq - out).abs().mean())

     1.3 Dynamic quantization on a decoder-only model

     standard initialization uses Kaiming-uniform A and zero B, so the adapter initially contributes exactly zero

 1   class LoRA(nn.Module):
 2       def __init__(self, original_layer, rank=8):
 3           super(LoRA, self).__init__()
 4           self.original_layer = original_layer
 5           self.rank = rank
 6           self.in_features = original_layer.in_features
 7           self.out_features = original_layer.out_features
 8
 9            # Match the standard LoRA initialization: A uses Kaiming uniform, B starts at zero.
10            # Transposing A for initialization gives Kaiming’s fan-in the input dimension.
11            self.A = nn.Parameter(torch.empty(self.in_features, rank))
12            nn.init.kaiming_uniform_(self.A.T, a=5 ** 0.5)
13            self.B = nn.Parameter(torch.zeros(rank, self.out_features))
14
15         def forward(self, x):
16             # The output is the original layer output plus the low-rank adaptation
17
18            # LoRA output
19            lora_output = (x @ self.A) @ self.B
20
21            # layer output, which combines the original output with the LoRA one
22            return self.original_layer(x) + lora_output
